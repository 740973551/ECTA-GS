# ECTA-GS · Alpha 0.1（M0/M1 首轮增量）

面向中国早期木构建筑研究的离线桌面资料工作台。此版本首先解决建筑档案和原始资料安全入库；尚未完成需求书中的全部 Alpha 功能。

## Windows 安装与启动

安装 Python 3.11 或 3.12（64 位，勾选 Add Python to PATH），在本目录打开 PowerShell：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m ecta_gs
```

如安装的是 Python 3.12，将 `-3.11` 改为 `-3.12`。首次安装需要联网下载依赖；软件正常使用不需要网络或 AI 密钥。本轮提供源码运行版，尚无 Windows exe 安装包。

也可双击 `start-windows.cmd`；第一次会创建虚拟环境并安装依赖。若系统有多个 Python，请使用上述明确版本的命令。

Linux/macOS 开发环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m ecta_gs
```

## 开始保存资料

1. 在“建筑档案”中新建建筑，填写已知字段；未知字段可留空，不预填历史事实。
2. 在“资料投喂”顶部选择本批建筑归属（默认“未分配资料箱”），填写来源说明。
3. 拖入文件/文件夹，或使用选择按钮。文件夹递归导入；符号链接跳过。
4. 每个文件复制并计算 SHA-256，完成后才提交数据库记录。相同内容、相同建筑不会重复建档；不同建筑可关联同一原件。
5. 选中资料查看哈希、时间、原件路径、基本文本/图片预览；修改建筑归属、来源和备注后点击保存。
6. 导入完成后关闭重开，档案、阶段和资料关联保留。

导入在后台线程进行。导入批次进行时阻止正常关闭窗口；若进程强制结束，已提交文件保留，未完成批次可重新导入，按哈希去重。失败项显示错误并写日志。输入文件不会被修改。解析状态统一明确显示“已保存，尚未解析”。

同一原件已在目标建筑存在时，重新归属会被拒绝，避免静默合并来源说明和备注。哈希对象不随建筑归属移动。当前没有删除原件的操作。

## 数据目录、备份、恢复

默认使用 `platformdirs` 的用户数据目录；Windows 通常为 `%LOCALAPPDATA%\ECTA-GS`。以设置页显示路径为准。数据库位于 `database/ecta.sqlite3`；原件位于 `library/objects/<哈希前两位>/<完整哈希>`，数据库保存原始文件名和扩展名。原件使用内容寻址，不以名称覆盖。

可在启动前指定独立资料库：

```powershell
$env:ECTA_GS_DATA_DIR = 'D:\ECTA-GS-Data'
.\.venv\Scripts\python.exe -m ecta_gs
```

- **完整备份**：等待导入结束、关闭软件，将整个数据目录复制到独立备份位置。
- 设置页“备份数据库快照”使用 SQLite 在线备份 API，快照保存在 `backups/`。此快照不包含原件，不能替代完整备份。
- **完整恢复**：关闭软件，先保留当前数据目录副本，将完整备份复制到一个新的空目录，再设置 `ECTA_GS_DATA_DIR` 指向该目录启动。不要覆盖或删除现有资料库。
- 数据库升级采用 Alembic；存在数据库且版本变化时先建立快照。迁移脚本随 Python 包安装，不依赖当前工作目录。没有自动降级删除表功能。
- 日志在 `logs/ecta.log`，按大小轮转。无外部 AI 调用，不收集 API 密钥。

本轮仅支持单个软件进程操作同一数据目录。不要在多台设备上同时写入同一同步目录；备份前应关闭软件。

## 实现状态

已实现 M0：安装入口、七页导航、本地数据库初始化/迁移、数据目录配置、轮转日志、数据库快照。

已实现 M1：建筑新建/编辑/搜索/归档、营建阶段新增/查看、拖拽多文件/文件夹导入、SHA-256 去重、未分配资料箱、归属修改、来源/备注、基本文本和图片预览、后台入库、持久化。

未实现：M2 格式解析器/任务队列/OCR/完整 PDF 预览；M3 AI Provider/提取/人工审核/修改历史；M4 知识检索和长期纠错记忆；M5 比较。对应页面明确标注待实现，不输出虚构结果。M1 来源和备注编辑尚不保存版本历史；知识审核历史在 M3 独立实现。

已知限制：文本仅预览前 64 KiB，非 UTF-8 按 GB18030 尝试，可能出现乱码；图片使用 Qt 读取，不支持的编解码会显示预览错误。任何格式均可保存原件，但保存不代表解析成功。大批量资料列表尚未分页。入库中断可能留下无数据库关联的完整哈希对象或临时片段；不自动清理原件，重新导入完整文件可复用完整对象。硬链接原子发布依赖本地文件系统支持，建议 NTFS；不支持时本次导入报错，不提交成功记录。无法保证硬件损坏下的数据完整性，应保持独立备份。
